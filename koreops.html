从漏洞判断到补丁执行，每一步都有依据

哪些主机需要修复、更新涉及哪些服务、变更经过谁审批，都能在平台中查询和核对。

01 / 定位风险

参考原厂评级，定位受影响主机

将 CVE 与主机、软件包版本关联，展示原厂漏洞评级及修复状态，帮助运维人员确定修复对象与优先级。

02 / 评估更新

查看关联服务，提前校验依赖

查询软件包关联的服务与更新记录，通过校验脚本检查补丁依赖、完整性和磁盘空间，为变更前评估提供具体依据。

03 / 核对执行

关联审批记录与执行证据

将审批意见与目标主机、补丁、脚本及重启策略关联，保留执行日志和结果，便于核对谁审批、谁执行，以及具体变更内容。

资产纳管

示意流程，非实时执行数据

深入了解：补丁执行五步与回滚边界按需展开

  1. 选择目标与通道

    按分组、IP 或标签选择主机，检查 Agent 在线状态与目标能力。离线或能力缺失时阻止执行。

  2. 配置预执行脚本

    在变更前运行预备脚本，按实际需要备份 YUM 缓存与关键配置。

  3. 校验执行条件

    检查补丁包完整性、依赖关系与磁盘空间，提前识别影响执行的条件。

  4. 设置重启策略

    根据业务窗口选择立即重启、延迟重启或不重启，明确本次变更的处理方式。

  5. 执行并回传结果

    通过 SSH、WinRM 或 Agent 执行，实时查看日志和进度，保留后续验证与回滚所需记录。

回滚支持 CVE、软件包及原作业批次维度，可控制时间窗口与并发范围。实际回退方案需结合软件包版本、备份和业务验证要求制定。

技术架构与部署

适配受限网络与现有运维体系

支持私有化与纯内网运行，复用已有补丁源，并对接机构现有的工单、资产和认证体系。

  • 跨平台：Linux / Windows，支持 SSH、WinRM 与 Agent
  • 补丁源：Linux 对接 Yum，Windows 对接内网 WSUS
  • 可连接 ITSM、CMDB、堡垒机与统一认证体系
  • 适配麒麟、统信、红帽、CentOS 等操作系统环境
查看基础部署参考与对接方式

执行体系由 Java 微服务、Ansible 与 KoreOps Agent 组成。Windows 可通过 WinRM 推装或命令安装 Agent，由 Agent 扫描、安装与回滚补丁。

最小化部署采用两台独立 Linux 主机，业务节点与执行节点不共机。单节点参考配置为 8 核 CPU、16 GB 内存、500 GB 硬盘，支持脚本化安装。正式配置需结合资产规模、并发窗口、日志保留周期和高可用要求评估。

执行节点可使用原生 Ansible 或 Ansible Tower / AAP。被管主机支持本机 Agent 与跳板 Agent 代管模式，漏洞情报库支持纯内网更新。

身份认证支持本地、LDAP / AD 和 OIDC；ITSM 或工单系统可通过 REST 触发流程，与既有运维体系对接。
